# 0.2026281.737 — feat(gh): bound and retry idempotent reads; writes stay single-attempt (#10)

Agent: `retention` · session `task-12` — cluster **C10a** of `plan/issue-ledger-2026-10-07.md`

## Summary

`ghkit` applied a fixed **60 s total** timeout with **no retry**, so a transient upstream stall failed
an idempotent read of a public listing outright — a load-period stall turned a bed red and then passed
3/3 on re-run (`opencharly/plugin-gh#10`).

The bound's SHAPE was the defect, so this change states the policy in one place and mechanizes it:

| | read (`GET`) | write (`POST`) |
|---|---|---|
| attempts | up to **4** | **exactly 1** |
| per-attempt bound | **20 s** | **60 s** (verbatim, unchanged) |
| total budget | **90 s** (attempts + backoff) | — |
| backoff | exponential, **full jitter**, ctx-cancellable | — |
| retried on | transport/timeout, `429` (honouring `Retry-After`), `502`/`503`/`504` | nothing |

- **A write is never retried.** A second attempt can duplicate a side effect; that is the R4 line and
  it is pinned by a test (`a stalled WRITE is attempted EXACTLY ONCE`), not by a comment.
- **A verdict is not a stall.** A `4xx` (except `429`) and a `2xx` are never retried. `500` is
  deliberately **not** on the retry list, and a test pins that boundary so the list cannot grow
  silently.
- **The decision lives on the METHOD**, not at each call site: `do` routes a GET to the retrying path
  and every other verb to the single-attempt path, so the write path stays retry-free as the package
  grows.
- **A failing read names its attempt count**, so "absorbed by policy" is distinguishable from a
  verdict. Per the Lead's ruling it rides the error message only, **never provenance** — that is a
  wire-visible surface owned elsewhere.

The body of a successful attempt is read INSIDE the attempt — on **both** paths — by one helper
(`releaseAttempt`), which hands back the same response carrying those bytes as an in-memory body. The
deadline can then be released without the CALLER's read being affected, and `readResponse` plus every
existing call site stay unchanged. On the write path that is not a nicety: a request context governs
the whole request lifetime *including the body read*, so releasing it before the caller read a
SUCCESSFUL POST's body failed the request with `context canceled` — the regression the first review
round caught, now pinned by a test whose body is still IN FLIGHT when the response is handed over.

## Review round — every finding of the BLOCK on `6b7320d`, one commit

| finding | disposition |
|---|---|
| **The write path cancelled its attempt before the caller's body read** (a successful POST failed with `context canceled`) | fixed: `releaseAttempt` reads in-attempt on both paths; the shared helper removes the duplication rather than adding a second copy |
| **"cancelling the caller's context stops the backoff" was vacuous** — it drove a `500`, which is not retryable, so no wait ever happened | fixed: replaced by a deterministic test of the primitive (`sleepCtx`) plus two race-free attempt-count cases |
| **The failure message hardcoded the attempt ceiling** and printed `(status 0)` for a transport-only failure | fixed: it names the attempts really made, and omits a status it never received |
| **`remainingBudget`'s dead `started` parameter** | fixed: dropped; it reads the budget context's own deadline |

The coverage the validator said was missing now exists, and each new case is proven by a targeted
mutation arm (below) — including the subtlety that a *buffered* localhost body hides the regression,
so the test's server flushes headers and leaves the body in flight.
