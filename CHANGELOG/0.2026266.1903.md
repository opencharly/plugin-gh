# 0.2026266.1903 — feat(gh): structured issue/PR document export + the ArtifactStore response cache

## Summary

Extend the canonical GitHub surface (`plugin-gh`) with a whole-issue-or-PR
`document` op and route every read through the ONE shared charly cache
ArtifactStore.

**New `document` op.** `gh: {op: document, repo: OWNER/NAME, number: N}` (verb)
or `charly gh document --repo OWNER/NAME --number N` (CLI) assembles a whole
issue OR pull request into ONE structured artifact: the body/labels/assignees,
EVERY issue comment, (PR) EVERY review and inline review comment, the commits,
and every changed file's unified patch AND complete content at head (fetched
from the git-blobs endpoint by the immutable blob SHA). The document is validated
against the served `#GhDocument` CUE def BEFORE it is written (R8), and emitted
as JSON or YAML to `--out` (or returned inline). ONE implementation serves both
surfaces.

**The shared response cache** (`gh/cache.go`) is the ONE
`github.com/opencharly/spec/cache` **ArtifactStore** (an OCI Image Layout,
spec#148) (R3): mutable reads revalidate by ETag (an unchanged upstream costs a
304, never a body refetch); immutable blob reads are component-keyed by SHA (a
repeat read never touches the network). `provenance.cached` records whether the
assembly served from cache.

### ArtifactStore cutover (this PR's cache is folded onto the new API)

`spec/cache.Store` (the keyed, one-JSON-file-per-key mechanism) was hard-cut over
to the content-addressed **ArtifactStore** (spec#148) before this PR could land —
the legacy `Store`/`Open`/`OpenNamed`/`ReadTTL`/`WriteValue` API is deleted, not
shimmed. So this PR's own cache is migrated in the same PR rather than landing on
a deleted API: `responseCache.store` is a `*cache.Layout`; constructors are
`cache.OpenLayout(dir)` / `cache.OpenNamedLayout("gh-http")`; the entry payload
field is `Entry.Payload` (was `Value`). The two validity modes and the in-process
memo are unchanged — only the storage shape moved to the OCI layout. The candy
plan's `plugin-gh-shares-cache-store` check is updated to `cache.OpenLayout`.

### Review round 4 — fixed (append-only commit `f7b9b45`)

- **B18/R7:** the emitted PR document read a non-existent API field
  (`PRMeta.ChangedSum` → `changed_lines`, which GitHub never returns) and never
  assigned `Deletions`, so every document reported a wrong `additions` and
  `deletions: 0` (both REQUIRED in `#GhPR`). Now maps the API's real
  `additions`/`deletions`, assigns both, and `TestAssembleDocument_PRTier1` pins
  them. Fail-without-fix proven: omitting `Deletions` fails 12/0 vs 12/5; live
  against `opencharly/plugin-gh#1` the document reports `281/26`, matching the
  API's `{additions: 281, deletions: 26}`.
- **R8/B13:** `validateDocument` failed OPEN — a nil validator returned success
  with only a stderr warning, so an unvalidated document could be written. It now
  fails closed, matching R8's unconditional "validated BEFORE it is written".
- **A1:** `README.md` accounted for above.
