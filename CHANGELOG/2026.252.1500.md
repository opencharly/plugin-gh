## plugin-gh: the canonical GitHub surface (bootstrap)

- The `verb:gh` check surface: `gh: {op: ..., repo: ..., pr: ...}` — ops pr_meta, pr_files, pr_diff, pr_commits, pr_thread, head_sha.
- The `command:gh` standalone CLI (`charly gh <op> --repo R --pr N`).
- `gh/ghkit`: the ONE GitHub REST client every opencharly plugin imports instead of hand-rolled `exec.Command("gh")` subprocesses. Explicit token resolution (GH_TOKEN → GITHUB_TOKEN → the gh hosts.yml auth), a pinned api.github.com base (never an ambiguous default-host redirect), and the HTTP status + response body surfaced on every non-2xx.
- Birth: RCA 2026.252.2233 — the eval lane's hand-rolled gh calls failed opaquely inside the executor subprocess (swallowed stderr, ambient-env dependence); the fix is a typed client with a declared contract, not another env var.
