# 0.2026267.723 — feat(gh): org/repo issues index op + Link-header pagination + anonymous-read + limit-boundary fixes

## Summary

Add an **`issues` list op** to the canonical GitHub surface — fetch every issue AND pull request for a **repo or an entire organization** as one compact, cached index — and fix the pagination and anonymous-auth defects the work surfaced.

### The `issues` op

`gh: {op: issues, org: opencharly}` (whole org) or `gh: {op: issues, repo: owner/name}` (one repo) lists issues AND pull requests as a compact `#GhIssueIndex`, the efficient discovery surface to pair with `document` (list cheaply, then fetch only the items you care about):

- **Org-wide in ONE paginated call** — `/orgs/{org}/issues?filter=all` returns every issue+PR across the whole org. (`filter=all` is REQUIRED: the endpoint defaults to `filter=assigned`, which silently under-lists.) This rides the **core** rate limit (5000/hr authed) rather than the search API's 10/min, and pages deterministically via the Link header.
- **Repo-scoped** — `/repos/{owner}/{repo}/issues`, public (no credential).
- Filters: `state` (open/closed/all), `kind` (issue/pr/all — applied client-side off the `pull_request` marker, since GitHub has no server-side issue-only filter here), `since` (incremental), `limit` (stops the walk exactly at a **page-level** boundary — see below), `include_body`.
- Each row carries `kind`, `repo`, `number`, `title`, `state`, `author`, timestamps, `url`, `labels`, `comment_count`, and — for a PR — `draft` and `merged_at`. `draft` IS a top-level issue field (proven: all 3840 org PR rows carry it); `merged_at` rides the row's `pull_request` member. **The head/base refs and SHA live on `/pulls` and are deliberately NOT claimed** (the `document` op fetches those). `repo` comes from `repository.full_name` on an org listing; the REPO endpoint returns no `repository` object, so a repo listing fills it from the requested slug (verified live). Validated against the served `#GhIssueIndex` CUE def before emission, serialized JSON/YAML.
- **Clean skip without a credential** — the org endpoint requires auth, so with no token the op returns a host-visible `skip` (never a fabricated listing, never a silent pass), honoring the "live or skip" contract.

### Efficiency fixes the work surfaced

1. **Link-header pagination (one mechanism).** List pagination now follows the Link header's `rel="next"` exclusively — the authoritative signal (verified against api.github.com: GitHub emits it iff there is a next page, so its absence is the exact terminator). The old page-count heuristic guessed from "a short page" and had no next-page cache. This is the ONLY mechanism; no fallback (R4). Each page rides the ETag-revalidated cache under its own URL, so a repeat listing costs one 304 per page and no body re-fetch — and a warm in-process memo replays the whole page set with zero requests.
2. **`PRCommits` and `PRThread` were not paginated at all** — they used a single `?per_page=100` `Get` and silently dropped any tail past 100. Both now page to completion (R1 defect fixed; the existing pagination tests' stubs now emit Link headers like the real service).
3. **Empty `Authorization` header broke anonymous reads.** `do()` unconditionally set `Authorization: Bearer <token>`; with an empty token that sent `Bearer `, which GitHub rejects with **401 "Bad credentials"** — turning an ordinarily-anonymous public read into a hard failure. The header is now set only when a token exists (verified: omitted → 200, `Bearer ` → 401).
4. **`limit` stops exactly at a page boundary.** The bound check is reported at the callback's **page level** (after the row loop), not inside it: a limit that lands exactly on a page boundary (e.g. `limit=100` with a full 100-row page) must stop after that page, not fetch the next one only to discard it. A row-loop-only check fetched-and-discarded in that case (fixed; `TestListIssues_LimitOnPageBoundaryStops` fails without the fix).
