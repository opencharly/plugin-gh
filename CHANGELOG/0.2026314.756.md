# 0.2026314.756 — refactor(schema): derive the gh word sets from vocabulary tables

## Summary

Convert the six inline `|` word unions in `candy/plugin-gh/schema/gh.cue` to
the §10.1 S3 vocabulary-table idiom, so each closed set of words has ONE home and
the enum a document meets is `or()` of that table's keys:

```
_op  _target  _format  _state  _kind          (+ their derived _…Word lists)
```

That is the 6 `union` rows `design/dpat-baseline.tsv` records for
`plugin-gh/candy/plugin-gh/schema/gh.cue` — **six single-line disjunctions**, all
pure word lists, no defaults, no scalar-type, heterogeneous or struct
alternatives. Every row this repo carried is retired by this PR; nothing is left
to judgement.

**Five tables cover six fields.** `_op` (8 words), `_format` (2), `_state` (3) and
`_kind` (3) are one field each; `_target` (2) covers BOTH the input's `target`
selector and the emitted `#GhDocument.kind`, because those are the same two-word
artifact kind — extracting on the second occurrence keeps the single home (R2).
